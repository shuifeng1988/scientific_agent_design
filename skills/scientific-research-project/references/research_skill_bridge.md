# Using installed research skills without losing project ownership

Read when preparing a deep appraisal or a substantive design review. This is an integration policy written for this project, not a copy of another Skill or its runtime. Keep scientific-research-project responsible for intake, approvals, five root documents, canonical task paths and Supervisor state.

## Select a bounded method provider

Inspect the current session's installed-skill catalog before assuming a provider exists. Read the selected provider's entry and only the relevant workflow/reference files; obey tool permissions, user scope and attribution. Do not install software, invoke paid APIs, upload private material or launch extra agents merely because an upstream example says to.

| Available provider | Useful bounded contribution | Integration boundary |
|---|---|---|
| academic-research-suite | Question/method alignment, source verification, thematic synthesis and critical review; inspect its deep-research workflow and relevant role prompts | No second master plan, phase directory tree, Passport or autonomous agent team. Preserve this project's 1–3 choice-assisted questions and real user waits; do not inherit a rule forbidding useful direct explanations |
| literature-review | Search design, deduplication, staged screening, primary-source extraction and citation checking | Distinguish targeted appraisal from systematic review; do not claim PRISMA compliance from a figure. No fixed prestigious-venue/citation-count admission rule or mandatory AI image generation in our independent protocol |
| deep-research (if offered by the host) | Clarification, following evidence leads, resolving material uncertainty, comprehensive readable synthesis | No assumed availability of the provider's UI/API. Map its artifact to existing project provenance or the registered result package; keep methods and audit records even if the provider's presentation style omits them |

If a provider is absent or incompatible with the approved task, use deep_research_gate.md and research_depth.md directly and disclose any unavailable search capability. These external providers are optional, not newly bundled dependencies. When applying their prompts, use only the bounded phase requested; do not claim all agents, hooks or online services from that package have run.

## Keep four distinct reasoning passes visible

Within the same appraisal/review record, perform and label these passes. They may be sequential work by the same Agent; never label them independent or cross-model unless actually performed that way.

1. **Question-to-method check:** can the intended observation distinguish the proposed explanation from its competitors? Identify the required unit, measurement, comparator and limitations before selecting software.
2. **Source-to-claim check:** separate citation identity verification from reading evidence that actually supports the statement. Preserve the observed passage/section/figure and access depth; an API match is not semantic validation.
3. **Across-study comparison:** group findings around the same scientific question, compare measurements and study designs, and explain conditional differences. Keep genuine unresolved disagreement instead of smoothing it into consensus. Do not count supporting papers as votes; reused cohorts are not independent replication.
4. **Evidence-to-decision challenge:** ask whether another explanation fits, whether the conclusion survives loss of its weakest assumption, and whether answering the question would change a scientific or practical decision. Record concrete defects and fixes; finding no defect is allowed. Do not manufacture criticism to meet a quota or refuse valid corrections to appear skeptical.

Connect the output to 00/01: each major gap/decision must point to a source-backed rationale, one or more detailed tasks, the data those tasks produce, and the inference permitted by those data. Use the existing research_depth.md substantive review with adequate/revise/needs_user outcomes. Critical unresolved evidence gaps cannot be relabeled minor limitations simply because a revision budget was exhausted.
