# Research design operating rules

These requirements are retained from the original project Skill. Reference paths below are relative to the scientific-research-project package root.

2. At project start or when scope is unclear, clarify goals, decisions, hypotheses, population, eligible models/data, endpoints, resources, exclusions, deliverables, expectations, and stopping rules. Read references/deep_research_gate.md and references/workflow_contract.md: use research_workflow.py draft for the two preliminary documents, conduct the actual literature/method appraisal, discuss it with the user, then freeze the five formal documents using hashed proposal, appraisal and user-decision evidence. Never manufacture approval or search records. The gate validates records and linkage, not human identity or scientific truth.

Read references/core_evidence.md: explicitly identify the primary evidence supporting the rationale, the data/comparisons that will decide this project's central claims, and independent corroboration/contrary evidence. Put this claim-to-evidence map in 00_PROJECT.md, bind each row to detailed 01_PLAN tasks and actual result locators, and distinguish planned evidence, external findings, project observations and Agent inference. Optional Skill attribution is methodological provenance, never scientific evidence.

After confirming direction, read references/research_depth.md together with references/deep_research_gate.md. 00_PROJECT.md must make a sourced argument from prior evidence and precise gaps to scientific/practical significance, contribution, null-result value and feasible evidence strategy. 01_PLAN.md must contain a detailed card and ordered substeps for every task: purpose, data, complete comparison scope, method/controls/statistics, commands or explicitly planned implementation, output schemas/paths, tables/figures, QC and what each artifact can support or refute. A roadmap table alone is inadequate. Deep research must examine actual sources, closest studies, recent and conflicting evidence and method feasibility, then show how findings determine the plan. Perform the substantive pre-approval review in research_depth.md; length, citation counts and schema passes are not evidence of depth. Do not expand the first clarification reply into this report or silently rewrite an existing frozen project.

New projects must use workflow_policy=plan_results_v1 in addition to execution_policy=v2. Read references/workflow_contract.md before drafting, freezing, reporting or enabling this policy. The daemon checks the approved design before new dispatch, and formal publication checks the canonical task path, run, report manifest, Markdown/Word contents, source tables, embedded figures, reflection and QC hashes. Render final reports from one manifest with research_workflow.py render; the analysis worker must first generate real tables, figures and interpretation. Keep batch drafts separate from the final receipt. Do not overwrite finalized receipts or downgrade the policy to bypass a failure. Existing projects require a reviewed migration: preserve their task IDs, evidence and hook, and never rerun completed research just to adopt the protocol. The new-project freeze command deliberately refuses to overwrite an existing registry or hook.
