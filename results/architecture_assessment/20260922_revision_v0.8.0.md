# 科研 Agent 修订记录：v0.8.0

日期：2026-09-22。本轮根据科研 Agent 评估实施源码修订，延续此前模块化架构。不是另一科研项目的方案变更，也未安装到用户级 Skill 目录或重启任何科研服务。

## 保留的特点

保留共享核心、8 个阶段 Skill、5 类角色；五个根文件仍是共同指导。保留真实澄清与方向确认、深入研究后讨论并批准设计、完整任务卡、计划任务与正式结果目录一一对应、实际数据/软件/方法/命令记录、表图、结果、结论、解释、README 与 Word 同源输出、反证和零结果、有界技术恢复、后台监控、事件追踪、会话日志隔离。技术中间产物仍可独立通过 QC，不为每个下载/分片增加完整报告。

完整特性追溯见 [FEATURE_PRESERVATION.md](../../documentation/FEATURE_PRESERVATION.md)。原编号 1–15 的核心条款仍保存在三个共享契约中。

## 已实施

总体架构图已更新为 v0.8.0，加入外部 literature-review provider、独立科学审阅、方案修订事务、补充分析节点和行为评价边界；原 v0.7.0 总体图作为历史版本保留。运行时 Agent 协作另见 [Agent 运行工作流图](figures/scientific_agents_runtime_workflow_v0.8.0.png)。

| 评估缺口 | 本次实现 | 验收边界 |
|---|---|---|
| 审阅与真实版本没有强绑定 | 新方案要求独立审阅策略；设计/结果绑定输入与产物哈希、作者和审阅调用、原始返回、逐项判断及缺陷处理 | 缺少、过期或存在重大未解决缺陷时不能冻结/正式交付；收据不是身份认证或科学正确性证明 |
| 科学等待被当作技术问题 | 新增 reviewing 状态，定期重查审阅/必要证据，不重新启动已完成计算、不消耗技术重试 | 独立分支仍可推进；不会自动生成通过的审阅 |
| Reviewer 权限主要靠提示词 | Codex 前台审阅入口显式使用 read-only sandbox，有限时和返回后哈希复查；Claude Reviewer 去掉 Bash/写工具 | 已测试调用参数和收据逻辑，未进行真实模型运行或安全渗透测试；宿主必须实际执行权限限制 |
| 冻结后缺少批准修订操作 | plan_amendment.py 保存历史基线、文档与映射；事务回滚/提交后事件重试；保留已完成旧版本报告 | 保守要求作业状态明确、daemon 锁可用；已有任务身份字段保持不变，替代科学任务使用新 ID；不自动重启服务 |
| 补充分析停在文字建议 | supplementary_tasks.py 登记同任务内的 artifact 节点；区分 required/optional，避免与自身最终完成形成死锁 | 必要节点完成且证据进入反思后才可交付；可选节点不阻止有效结论；新科学范围仍需批准修订 |
| 外部模块输入/产出约束不完整 | schema-2 请求记录输入哈希、结果 run、审阅对象、时间/产物大小上限；各阶段检查标准载荷；本地入口指纹检查 | 输入清单仍需操作员覆盖实际数据/模型/代码；验收上限不是运行时资源隔离；远程版本需宿主核验 |
| 外部文献模块缺少具体接入 | literature_adapter.py 检查安装入口、生成配置，保存原始输出/工具/访问限制并转换为已有 appraisal 交接 | 安装入口已实查；离线合成输出转换通过；未完成在线课题检索 |
| 没有科研行为评价工具 | 6 个合成案例、分离的人工评分标准、真实响应/评分收据绑定、严重错误单列及同输入/模型/工具/预算对比 | 未运行真实模型 A/B 评估；不能宣称科学质量、速度或成本已有提升 |

## 验证方法与结果

在隔离临时目录中运行：

```bash
python3 -B -m unittest discover -s skills/scientific-research-project/scripts -p 'test_*.py' -q
```

结果：**126 项测试通过**，最终一轮 11.103 秒。涵盖既有设计/报告/调度/恢复测试，以及审阅版本/独立调用记录、重大缺陷拒绝、旧基线兼容、审阅等待不重复执行、批准修订与回滚/恢复、旧报告保留、新范围门槛重绑定、必要补证据与死锁拒绝、provider 输入漂移/超时/大小限制、只读 reviewer 参数/超时/篡改拒绝、外部文献标准化交接、人工评价待审状态和公平比较约束。

9 个 Skill 均通过 skill-creator 的 quick_validate；中英文 README 结构/命令对应检查包含在测试中；git diff --check 通过。测试中模型、人工审阅与检索记录均明确标记为合成夹具，不代表科研能力实测。运行前已有的 tracked pyc 修改未作为本次实现改动处理。

## 使用与兼容

详细命令、JSON 字段和限制集中在[科研治理协议](../../skills/scientific-research-project/references/scientific_governance.md)及[外部模块契约](../../skills/scientific-research-project/references/provider_contract.md)。核心入口和阶段 Skill 按需读取这些协议，不把详细逻辑重新塞回一个大 Skill。

新设计强制独立审阅；已冻结旧设计保留原有策略直到真实批准迁移。方案变更不重写已完成成果；修订只创建新基线并保留历史解释。源码更新、安装更新、具体研究方案修订和已批准基线迁移仍是不同操作。

当前仍需真实任务验证：文献检索质量、统计判断、独立 Reviewer 的实际识错能力、完整 Claude 调用链，以及模块化对耗时/token/费用的净收益。可用新增案例与实际领域任务收集这些证据，不能由本轮程序测试推断。
